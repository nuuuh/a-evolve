ENVIRONMENTAL CONSTRAINTS
--------------------------

Docker environment limits bash effectiveness:

1. Network Isolation
   - No direct internet access for curl/wget
   - Most HTTP requests return 302/403/connection errors
   - BusyBox environment, not full bash (e.g., no grep -P)

2. Temporal Filters
   - Infra modules filter post-cutoff data by design
   - Prevents leakage but frustrates agents
   - Retry attempts are futile

3. Container Restrictions
   - Limited file system access
   - No persistent state between commands
   - Container errors when accessing /tools/


COGNITIVE IMPACT
-----------------

Bash shifts agent into "programming mode":

1. FOCUS SHIFT
   Without bash: Research → Reason → Answer
   With bash:    Research → Debug → Program → (stuck) → Wrong answer

2. TURN BUDGET
   No-bash agents use turns for information gathering
   Bash agents burn turns on:
     - Discovering infra modules (ls /tools/, cat files)
     - Debugging network errors
     - Parsing HTML/JSON with one-liners
     - Retrying blocked queries

3. COGNITIVE LOAD
   Bash expands possibility space from:
     "What should I search for?"
   To:
     "Should I search or script? Which API? How to parse? Why is grep failing?"
   
   Paradox of choice leads to suboptimal decisions
