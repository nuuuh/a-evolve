\section{Related Work}
\label{sec:related}

\noindent\textbf{Self-evolving agents.}
A-Evolve~[cite] introduces the basic linear-chain evolver: each cycle reads batch trajectories and mutates prompts, skills, memory, and tools. GEPA~[cite] (NeurIPS 2025) adds reflective Pareto prompt evolution using textual feedback rather than scalar reward. Meta-Harness~[cite] (2026) uses a growing filesystem archive and Claude Code as the proposer. OctoTools~[cite] (ACL 2026 oral) is a training-free generalist Planner+Executor+Tool-Cards system. These systems are primarily evaluated on i.i.d.\ benchmarks (HotpotQA, MATH, GAIA, MMLU-Pro, MedQA) where D1, D2, and D3 are absent or bounded. In contrast, we characterise three task-intrinsic failure modes these systems exhibit on deployment-like streams, name and separate the underlying mechanisms, and introduce three architectural remedies.

\noindent\textbf{Retrieval-augmented and mixture-of-experts systems.}
RAG~[cite] and MoE~[cite] retrieve or route over pre-built indices or expert populations. Our agentic navigation differs in four respects: retrieval units are executable git branches, not document chunks; branches have evolutionary lineage (fork / merge); the router operates on README / system-prompt content rather than embedding similarity; and total capacity is partitioned across branches rather than retrieved as top-$k$.

\noindent\textbf{Continual learning and distribution shift.}
The broader ML literature on domain adaptation, continual learning, and test-time adaptation motivates our $\Lnav$ framing~[cite]. Our contribution is instantiating these ideas at the \emph{harness} level (prompt + skills + tools + infrastructure) for LLM agents, rather than at the model-weights level. This allows the adaptation mechanism (per-task routing) to be decoupled from the learning mechanism (multi-agent construction), the key to the orthogonal decomposition $\Levo + \Lnav$ developed in \S\ref{sec:method}.

\noindent\textbf{Human-in-the-loop agent systems.}
HITL agent supervision has been studied primarily as always-on oversight or per-step gating~[cite]. Our contribution (\S\ref{sec:method-hitl}) is a \emph{structurally triggered} HITL: hooks fire only when evolver-internal signals (failed API authentication, novel-vocabulary tasks) indicate that the input history itself is insufficient, and the intervention type is scoped to credential provision or task-board direction --- targeted at the experience-availability axis, not at general solver supervision.
