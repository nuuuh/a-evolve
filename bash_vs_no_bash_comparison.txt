KEY INSIGHTS
------------

1. BASH ENABLES BAD HABITS
   - Echo spam for "thinking aloud"
   - Curl retry loops despite network blocks
   - Temporal filter bypass attempts
   - Python one-liner "solutions" that don't help

2. NO-BASH FORCES DISCIPLINE
   - Must use web_search effectively
   - Can't waste turns on technical debugging
   - Focuses agent on reasoning from available data
   - Faster convergence to answer

3. SUCCESSFUL BASH IS RARE AND SPECIFIC
   - Only works when agent knows exact infra module to call
   - Requires specific query structure (Manifold market URL, financial API)
   - Even then, web_search often finds same data faster

4. DOCKER ENVIRONMENT LIMITS BASH
   - No direct internet access (curl/wget fail)
   - Temporal filters block post-cutoff data
   - Container isolation prevents file system tricks
   - BusyBox limits available commands (e.g., no grep -P)

5. COGNITIVE LOAD
   - Bash shifts agent into "programming mode"
   - Loses sight of prediction task
   - Debugging replaces reasoning
   - Turn budget wasted on technical issues


RECOMMENDATIONS
---------------

1. IMMEDIATE: Remove bash from FutureX solver
   Expected impact: +45-50% success rate

2. IF BASH MUST STAY: Strict constraints
   - Max 3 bash commands per task
   - Only allow /infra/search_pipeline.py and /infra/http_client.py
   - Block all curl/wget/echo/cat commands
   - Add turn limit: if bash fails twice, disable it for remainder of task

3. ALTERNATIVE: Purpose-built tools
   Instead of bash access, create:
   - manifold_query(market_url) → resolved market data
   - financial_data(symbol, date) → price data

4. IMPROVE WEB_SEARCH
   Analyze the 3 successful bash cases:
   - Can web_search return same Manifold data?
   - Can web_search access financial APIs?
   If yes, enhance web_search and remove bash entirely
